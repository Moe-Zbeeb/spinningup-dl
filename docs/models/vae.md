## Background

A **variational autoencoder**, or **VAE**, is a generative model: it learns to produce new data that looks like its training data. It has two parts. An **encoder** compresses each image into a small vector of **latent variables** $z$, and a **decoder** turns latent vectors back into images. Training makes two things true at once: the decoder can reconstruct each image from its encoding, and the encodings of all the images together look like samples from a simple distribution, a standard normal. Then, to generate a new image, draw $z$ from that normal distribution and decode it.

### Quick Facts

- Input: images. Output: reconstructions of them, and new images sampled from the latent space.
- The latent space is smooth: nearby points decode to similar images, so moving between two points morphs one image into the other.
- Training is stable and fast, but samples tend to be blurrier than those of [diffusion models](diffusion.md).
- Use it to learn compact representations, to generate data, and to detect unusual inputs, which reconstruct poorly.

### Key Equations

The encoder outputs a mean $\mu$ and a log variance $\log \sigma^2$ for each latent variable, describing a normal distribution $q(z \mid x)$ over the encodings of $x$. To sample from it while keeping the computation differentiable, the **reparameterization trick** writes

$$
z = \mu + \sigma \odot \epsilon, \qquad \epsilon \sim \mathcal{N}(0, I),
$$ (eq-vae-reparam)

so the randomness is in $\epsilon$, and gradients flow through $\mu$ and $\sigma$. The decoder maps $z$ to an image $\hat{x}$. The loss for one image has two terms:

$$
\L(x) = \underbrace{-\sum_{j} \left[ x_j \log \hat{x}_j + (1 - x_j) \log (1 - \hat{x}_j) \right]}_{\text{reconstruction}} + \underbrace{\left(-\frac{1}{2} \sum_{k} \left(1 + \log \sigma_k^2 - \mu_k^2 - \sigma_k^2\right)\right)}_{\text{KL divergence}}.
$$ (eq-vae-loss)

The reconstruction term, a binary cross-entropy over the pixels $j$, rewards accurate reconstructions. The second term is the **Kullback-Leibler divergence** between $q(z \mid x)$ and the standard normal, which pulls every encoding toward $\mathcal{N}(0, I)$. The two pull against each other: the KL term alone would make every encoding identical, and the reconstruction term alone would scatter them anywhere. Their sum, called the negative **evidence lower bound**, balances the two. Its value, and both terms, are logged as `TestLoss`, `TestReconstruction`, and `TestKL`.

### Pseudocode

```text
Algorithm 1  Training a VAE

for epoch = 1, 2, ..., epochs do
    for each mini-batch X of the training set do
        μ, log σ² ← encoder(X)
        Sample ε from a standard normal, and set Z ← μ + σ ⊙ ε, equation (1)
        X̂ ← decoder(Z)
        Compute the loss, equation (2), averaged over the batch
        Update the encoder and decoder with Adam
    end for
    Log the test loss and its two terms, and save the model
    Decode 64 latent vectors drawn from a standard normal, and save them as an image
end for
```

## Documentation

```python
spinup_dl.vae(dataset="mnist", hidden_size=400, latent_dim=20, epochs=10, batch_size=128, lr=1e-3, weight_decay=0.0,
              optimizer="adam", seed=0, device="auto", num_workers=0, logger_kwargs=dict())
```

Trains a VAE and returns it.

| Argument | Meaning |
| --- | --- |
| `dataset` | `mnist`, `fashion_mnist`, `cifar10`, or `fake` |
| `hidden_size` | Units in the hidden layer of the encoder and of the decoder |
| `latent_dim` | Number of latent variables |
| `epochs`, `batch_size`, `lr`, `weight_decay`, `optimizer`, `seed`, `device`, `num_workers`, `logger_kwargs` | As for the [MLP](mlp.md#documentation) |

The model class is `spinup_dl.models.vae.VAE(image_shape, hidden_size, latent_dim)`. Its `sample(n, device)` method generates `n` new images.

### What to Expect

```bash
python -m spinup_dl.run vae --epochs 30
```

This run took a minute. The test loss was 103.0 per image: 77.2 for the reconstruction and 25.8 for the KL term. These are 64 images it generated:

```python
model = load_pretrained("vae_mnist")
```

### Things to Try

- Train with `--latent_dim 2`. Then encode the test set and plot the two latent variables, colored by digit, to see how the VAE organizes the digits.
- Decode a line of points between the encodings of two test images, to watch one digit morph into another.
- Compare `--latent_dim 2 20 100` on `TestReconstruction` and `TestKL`.

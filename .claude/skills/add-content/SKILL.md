# Adding Content to Spinning Up in Deep Learning

## Overview

The site is a Sphinx project in `docs/`, written in MyST Markdown, themed with `sphinx_rtd_theme` and one stylesheet, `modify.css`, ported from OpenAI's Spinning Up so the fonts, link colors, and layout match that site. Only the name and logo are AUB Frontier AI Fellows (AUB–FAF). A page is one `.md` file. A page appears in the sidebar only when a `toctree` in `docs/index.md` lists it.

`AGENTS.md` at the repository root holds the house style and the workflow for typesetting notes; read it first. This skill holds the mechanics. `templates/` holds the shape of a part, a section, a model page, and a placeholder.

`docs/etc/style-guide.md` is the live reference for every element (math, callouts, code, tables, figures, footnotes). Read its source before writing a page and copy from it. It renders at `/etc/style-guide.html`.

## Where Things Live

| What | Where |
| --- | --- |
| Landing page and sidebar order | `docs/index.md` |
| Pages | One folder per sidebar section: `docs/user/`, `docs/intro/`, `docs/resources/`, `docs/models/`, `docs/etc/`. New sections get a new folder |
| Element reference page | `docs/etc/style-guide.md` |
| Page and section templates | `templates/part.md`, `templates/section.md`, `templates/model.md`, `templates/placeholder.md` |

| Site name, extensions, math macros, GitHub repo | `docs/conf.py` |
| Deploy on push to `main` | `.github/workflows/deploy.yml` |

## Tasks

### Fill in a placeholder page

Every unwritten page outside `docs/intro/` holds a single `Coming soon` box. Open the file, delete the whole ` ```{admonition} Coming soon ` block, keep the `# Title` line, and write the page below it. Nothing else needs to change: the sidebar and landing page read the title and the `##` headings from the file.

### Fill in one section of an Introduction to Deep Learning part

The five parts in `docs/intro/` are outline pages: a `Coming soon` box at the top, then one `##` heading per topic with `*Coming soon.*` under it. To write a topic, replace the `*Coming soon.*` line under its heading with the content, in the shape of `templates/section.md`, using `###` for subsections. Leave the other headings as they are. When the first topic of a part is written, whichever heading it is, add the part's opening paragraph under the `Coming soon` box, as in `templates/part.md`. When the last topic is written, delete the `Coming soon` box at the top and add a `## Recap` section at the end; the checker requires both. To add, rename, or reorder topics, edit the `##` headings: the sidebar, the landing page, and the page's table of contents all follow them.

| Part | File |
| --- | --- |
| Part 1: Neural Networks and Deep Learning | `docs/intro/neural_networks.md` |
| Part 2: Improving Deep Neural Networks | `docs/intro/improving_networks.md` |
| Part 3: Structuring Machine Learning Projects | `docs/intro/structuring_projects.md` |
| Part 4: Convolutional Neural Networks | `docs/intro/convnets.md` |
| Part 5: Sequence Models | `docs/intro/sequence_models.md` |

### Add a new page to an existing section

1. Create `docs/<section>/<name>.md`. Use a short lowercase file name with underscores, such as `docs/models/resnet.md`. The file name becomes the URL.
2. Start the file with one `# Title`. That title is the sidebar label.
3. If the page is not written yet, give it the placeholder box below the title and nothing else:

   ````markdown
   # Residual Network

   ```{admonition} Coming soon
   This page is being written. It will cover background, key equations, pseudocode, and documentation for residual networks.
   ```
   ````

4. Add `<section>/<name>` (no extension) to the matching `toctree` in `docs/index.md`, at the position it should appear in the sidebar.

### Add a new section to the sidebar

1. Create a folder `docs/<section>/` and at least one page file in it, as in the steps above.
2. Add a `toctree` block to `docs/index.md`. The `:caption:` is the section label. Sections appear in the sidebar in the order their blocks appear in the file, so place the block where the section belongs. Keep `:maxdepth: 2`. Every line in the block must match a file that exists.

````markdown
```{toctree}
:maxdepth: 2
:caption: Advanced Topics

advanced/normalization
```
````

### Rename, move, or remove a page

Rename or delete the file, update its line in `docs/index.md`, then search `docs/` for links to the old path and fix them. `make check` fails on any link or toctree entry that points to a missing page.

### Publish a page that is not ready

Leave the `Coming soon` box in place, or keep the page out of every `toctree` and put this at the very top of the file so the build does not warn about it:

```markdown
---
orphan: true
---
```

## Page Shape

One `#` title per page, then `##` sections, then `###` subsections. As on Spinning Up, every written content page opens with a table of contents directly under the title:

````markdown
```{contents} Table of Contents
:depth: 2
```
````

 The sidebar and the landing page show `##` headings under each page, so write them as short labels in Title Case, as Spinning Up does ("Key Concepts and Terminology", not "Let's look at some key concepts").

A concept page (the Introduction to Deep Learning parts) reads top to bottom: what the reader will learn, the ideas in the order they depend on each other, a recap.

A Models Docs page follows the Spinning Up algorithm-page outline:

```markdown
# Multilayer Perceptron

## Background

### Quick Facts

### Key Equations

### Pseudocode

## Documentation

## References

### Relevant Papers

### Other Public Implementations
```

| Heading | What goes under it |
| --- | --- |
| Background | What the model is, what problem it was built for, and what the reader should already know, with a link to the page that teaches it |
| Quick Facts | Three to five bullets: input and output, what the model assumes about the data, when to use it |
| Key Equations | The forward computation and the loss, each symbol defined right after the equation |
| Pseudocode | The algorithm in a `text` block |
| Documentation | A minimal PyTorch implementation with a usage example. When the site gains a companion code package, this becomes the reference for that package's implementation |
| Relevant Papers | A plain bulleted list of the papers that introduced or shaped the model, each as a link with authors and year |
| Other Public Implementations | Links to well-known implementations elsewhere |

## Elements

Links to other pages are relative paths ending in `.md`: `[Part 1](../intro/neural_networks.md)`. Link to a section with `[text](../intro/neural_networks.md#section-heading-in-lowercase-with-hyphens)`.

Math uses `$...$` inline and `$$...$$` for display. Multi-line math uses `aligned` inside the dollar signs. To number an equation, put a label in parentheses on the same line as the closing `$$`. Refer to it in the text with the `eq` role. Labels are shared across the whole site, so each one is `eq-`, then the page's file name with underscores written as hyphens, then a short name: `eq-mlp-forward` in `mlp.md`, `eq-improving-networks-adam` in `improving_networks.md`. The checker enforces the prefix. A function defined piece by piece uses `\begin{cases}`.

```markdown
$$
\begin{aligned}
z &= Wx + b \\
a &= \max(0, z)
\end{aligned}
$$ (eq-mlp-layer)

The second line of {eq}`eq-mlp-layer` is the ReLU.
```

Site-wide macros are `\R`, `\E`, `\L`, `\argmax`, `\argmin`. Add more under `mathjax4_config` in `docs/conf.py` when a symbol is used on more than one page.

Callout boxes are admonitions. The box title is free text. "You Should Know" is the default box, used for a convention the reader will meet elsewhere, a caveat, a common mistake, or a pointer to further reading.

````markdown
```{admonition} You Should Know
The body of the box. It can hold paragraphs, math, lists, and code.
```
````

| Box | Syntax | Use for |
| --- | --- | --- |
| You Should Know | `{admonition} You Should Know` | Conventions, caveats, common mistakes, pointers to further reading |
| Note | `{note}` | Asides |
| Tip | `{tip}` | Practical advice |
| Warning | `{warning}` | Mistakes that cost time |
| Optional sidebar | `{sidebar} (Optional) Title` | A derivation the reader can skip, floated to the right of the text; place it at the top of its section |
| Coming soon | `{admonition} Coming soon` | Unwritten pages and sections |

Code blocks always name a language (`python`, `bash`, `text` for pseudocode). Code examples use PyTorch and must run as written. The site build does not execute code and the build environment has no PyTorch, so run each example in an environment that has `torch` before publishing it. If that is not possible, tell the user the example is unverified.

Figures go in `docs/_static/img/<page-name>/` and are placed with `figure` so they carry a caption. The path is relative to the page file. Prefer SVG for diagrams and PNG at twice the display size for plots.

````markdown
```{figure} ../_static/img/mlp/architecture.svg
:alt: A three-layer perceptron with two hidden layers.
:width: 80%

What the reader should notice in the figure.
```
````

A footnote backs a specific claim in the text: `[^adam]` at the claim and `[^adam]: Kingma and Ba, [Adam: A Method for Stochastic Optimization](https://arxiv.org/abs/1412.6980), 2015.` as the last lines of the file. Footnotes always render at the very bottom of the page, whatever heading the definition sits under, so never put footnote definitions under a heading such as Relevant Papers: the heading would render empty. A reading list is a plain bulleted list. The same paper may appear in both.

## Voice

The house style is in `AGENTS.md` under House Style: "we" speaking to "you", short paragraphs with one idea each, a term in bold where it is defined, a sentence leading into each equation and another explaining its symbols, a small concrete example before the general rule. Headings are labels, not sentences.

## Design Reference

The look is OpenAI's Spinning Up: the Read the Docs theme plus `docs/_static/css/modify.css`, a port of Spinning Up's own `modify.css`. Fonts and colors are set there and nowhere else. Pages never set fonts or colors themselves.

| Element | Value |
| --- | --- |
| Body font | `"Lato", "proxima-nova", "Helvetica Neue", Arial, sans-serif`, 16px, line height 24px. Lato ships with the theme, so every reader sees it |
| Heading font | The same Lato stack, bold. `h1` 28px, `h2` 24px, `h3` 20px |
| Code font | `SFMono-Regular, Menlo, Monaco, Consolas, "Liberation Mono", "Courier New", Courier, monospace`, 12px in blocks |
| Math | MathJax default (Computer Modern) |
| Body text | `#000` |
| Links | `#2e95d3` (`--color--mediumblue`), visited `#9b59b6` |
| Sidebar | `#404452` (`--color--coolgray4`) background, links `#8e8ea0`, section labels `#c5c5d2` uppercase with 1px letter spacing |
| Sidebar header, current item, callout bodies, striped table rows, page margin | `#eeedee` (`--color--warmgraylight`) |
| Content column | `#fcfcfc`, 800px wide, beside a 300px sidebar |
| Callout title bar | `#2e95d3` with white bold text |
| Inline code | `#e74c3c` on white with a `#e1e4e5` border (theme default) |
| AUB maroon | `#840132` (`--color--maroon`), used only in the logo |

The landing page is, in order: the `#` title, the banner image, then the `toctree` blocks. Nothing else goes on it.

Diagrams and plots made for the site use a white or transparent background and the palette above: `#2e95d3` for the thing being discussed, `#404452` for everything else, `#eeedee` for fills.

To change the logo text, edit `tools/logo.html`, run `make html`, open the file in a browser at 1000 by 408 pixels, and save a screenshot over `docs/_static/img/logo.png`. To change the banner, edit `tools/banner.py` and run `python3 tools/banner.py docs/_static/img/banner.svg`.

## Build, Preview, Publish

```bash
make setup
make serve
make check
```

`make setup` is needed once per machine. `make serve` opens a live preview at `http://localhost:8000` that reloads on save. `make check` is the gate: it runs the template checker, then builds with warnings as errors, exactly as the deploy workflow does, and writes the HTML to `docs/_build/html/`. `make lint` runs the checker alone. Its messages name the file, the line, and the rule that was broken.

A page is done when `make check` passes and the rendered page has been looked at. Math is drawn by MathJax in the browser, so reading the HTML file proves nothing: use the live preview, or run `make shot PAGE=intro/neural_networks`, which saves a screenshot of the built page to `docs/_build/shots/` and prints its path (add `HEIGHT=6000` for a long page). The build cannot see an empty heading, a broken equation, or a figure at the wrong size; only looking can.

Publishing is a commit and a push to `main`. The GitHub Actions workflow rebuilds and deploys the site. Commit and push when the user asks to publish, or has said to publish each section as it is finished.

## Common Mistakes

| Symptom | Cause | Fix |
| --- | --- | --- |
| `document isn't included in any toctree` | New page not listed in `docs/index.md` | Add it to a `toctree`, or mark it `orphan: true` |
| `toctree contains reference to nonexisting document` | Path in `docs/index.md` is wrong or has an extension | Use `section/name` with no `.md` |
| "Erroneous nesting of equation structures" on the page | `\begin{align}` inside `$$` | Use `\begin{aligned}` |
| `cross-reference target not found` | Link path is not relative to the current file, or lacks `.md` | Fix the relative path |
| Page title missing from the sidebar | File has no `#` heading, or has two | Exactly one `#` heading, first in the file |
| Raw `$` signs showing in the text | Space after the opening `$` or before the closing one | Remove the spaces |
| Image not found | Path written from the repo root | Write it relative to the page file |
| A heading renders with nothing under it | Only footnote definitions were placed there | Put a bulleted list under the heading and move the footnotes to the end of the file |
| `duplicate label of equation` | Two pages use the same equation label | Prefix labels with the page name |
